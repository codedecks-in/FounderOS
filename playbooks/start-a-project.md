# Playbook: Start a Project

**Owner:** Founder / product lead  
**Inputs:** Product idea, known evidence, constraints  
**Outputs:** Project brief, discovery artifact, prioritized questions, next-stage decision

## Procedure

1. Create a project workspace with `docs/`, `decisions/`, and `modules/`; copy the relevant FounderOS templates into it. Keep project artifacts separate from reusable FounderOS guidance.
2. State the user problem and intended outcome. Record what is observed, sourced, inferred, or unknown; do not turn an assumption into a fact by repeating it.
3. Run discovery and targeted market/customer research. Capture source, date, sample, limitations, and confidence for evidence.
4. Define target users, alternatives, success measures, non-goals, risks, and open decisions. Keep the smallest testable scope visible.
5. Review findings with the founder. Decide `Proceed`, `Research more`, or `Stop`; record rationale and approval in the discovery artifact.
6. If proceeding, create a PRD, assign requirement IDs, and define testable acceptance criteria. Do not make architecture choices in the PRD.
7. Obtain explicit approval before architecture and implementation planning begin.

## Gate

Proceed only when a specific user problem, evidence gaps, target segment, success measure, non-goals, and decision owner are documented. If critical evidence is missing, name the research action and owner instead of approving by default.
